# Схема базы данных проекта ChargeFlow


## Таблица `users_new`

**Описание:** Основная таблица пользователей платформы. Хранит данные профиля, учетные данные для входа в Личный Кабинет и информацию о ролях (Права доступа).

### 1. Структура полей (Columns)

| Столбец | Тип данных | Nullable | По умолчанию | Описание |
| :--- | :--- | :--- | :--- | :--- |
| **id** | `integer` | NO | `nextval` | Первичный ключ (Primary Key) |
| **full_name** | `text` | NO | - | Полное имя пользователя / Инвестора |
| **email** | `text` | NO | - | Электронная почта (Логин для входа) |
| **hash_password** | `text` | NO | - | **Хешированный** пароль (bcrypt/argon2) |
| **company** | `text` | YES | `NULL` | Название компании инвестора |
| **phone** | `text` | YES | `NULL` | Контактный номер телефона |
| **country** | `text` | YES | `NULL` | Страна / Регион присутствия |
| **created_at** | `timestamptz` | YES | `now()` | Дата регистрации в системе |
| **updated_at** | `timestamptz` | YES | `now()` | Дата последнего изменения профиля |
| **role** | `text` | YES | `'investor'` | Роль пользователя (`investor` или `admin`) |

### 2. Индексы и Ограничения (Indexes & Constraints)

*   **PK**: `users_new_pkey` — идентификатор пользователя.
*   **Unique**: `users_email_unique` — запрещает регистрацию нескольких аккаунтов на один email.
*   **Check**: `users_new_role_check` — строгое ограничение ролей. Допустимы только `investor` или `admin`.
*   **Referenced by**: На эту таблицу ссылается `operator_credentials` через внешний ключ `user_id`.

### 3. Безопасность (Security Notes)

*   **Пароли**: В столбце `hash_password` никогда не хранятся пароли в чистом виде. Используется криптографическое хеширование с солью.
*   **Доступ**: Доступ к данным ограничен уровнем JWT-токенов. Инвестор может видеть только свои данные и связанные с ним зарядные станции.

## Таблица `operator_credentials`

**Описание:** Хранит учетные данные для авторизации во внешних API операторов электрозарядных станций (ЭЗС). Все чувствительные данные (логины, пароли, ключи) шифруются перед записью в базу.

### 1. Структура полей (Columns)


| Столбец | Тип данных | Nullable | По умолчанию | Описание |
| :--- | :--- | :--- | :--- | :--- |
| **id** | `bigint` | NO | `nextval` | Первичный ключ (Primary Key) |
| **user_id** | `integer` | YES | `NULL` | ID пользователя (Связь с `users_new.id`) |
| **auth_type** | `text` | YES | `'basic'` | Способ аутентификации (например, basic, bearer) |
| **is_active** | `boolean` | YES | `true` | Статус активности данной интеграции |
| **login** | `text` | YES | `NULL` | **Зашифрованный** логин для внешнего API |
| **password** | `text` | YES | `NULL` | **Зашифрованный** пароль для внешнего API |
| **operator** | `text` | YES | `'volt'` | Идентификатор или название оператора ЭЗС |
| **api_key** | `text` | YES | `NULL` | **Зашифрованный** токен доступа (API Key) |
| **paid_until** | `timestamptz`| YES | `now()` | Срок действия доступа или оплаты |
| **created_at** | `timestamptz`| YES | `now()` | Время создания записи в системе |
| **updated_at** | `timestamptz`| YES | `now()` | Время последнего изменения данных |

### 2. Индексы и Ограничения (Indexes & Constraints)

*   **PK**: `id` — основной идентификатор записи.
*   **Unique**: `user_id` — гарантирует уникальность связки пользователя и учетных данных (один аккаунт на одного юзера).
*   **FK**: `user_id` -> `users_new.id` — прямая связь с таблицей пользователей.
*   **Index**: `user_id_idx` — ускоряет выборку данных при входе пользователя в личный кабинет.

### 3. Безопасность (Security Notes)

*   **Шифрование**: Поля `login`, `password` и `api_key` зашифрованы на стороне приложения (Backend) перед попаданием в БД. В сыром виде данные в базе нечитаемы.
*   **Доступ**: Прямой доступ к таблице извне закрыт. Чтение/запись разрешены только авторизованным сервисам внутри защищенной сети проекта.


## Таблица `bi_exports`

**Описание:** Таблица логирования и управления процессами экспорта данных Business Intelligence (BI). Хранит метаданные запусков, параметры фильтрации, статусы генерации отчетов и ссылки на готовые файлы в облачном хранилище S3.

### 1. Структура полей (Columns)

| Столбец | Тип данных | Nullable | По умолчанию | Описание |
| :--- | :--- | :--- | :--- | :--- |
| **id** | `bigint` | NO | `nextval` | Первичный ключ (Primary Key), автоинкремент |
| **run_id** | `text` | NO | - | Уникальный идентификатор запуска процесса экспорта |
| **user_id** | `bigint` | NO | - | Идентификатор пользователя, инициировавшего выгрузку |
| **operator** | `text` | NO | - | Оператор или внутренняя система, выполняющая экспорт |
| **type_method** | `text` | NO | - | Метод или тип выгружаемых данных / отчета |
| **run_mode** | `text` | NO | - | Режим запуска задачи (например, ручной или автоматический) |
| **s3_key** | `text` | NO | - | Путь (ключ) к сгенерированному файлу отчета в бакете S3 |
| **status** | `text` | NO | `'pending'` | Текущий статус обработки задачи (например, `pending`, `success`, `failed`) |
| **error** | `text` | YES | `NULL` | Текст технической ошибки в случае сбоя генерации отчета |
| **created_at** | `timestamptz` | YES | `now()` | Дата и время создания задачи на экспорт |
| **updated_at** | `timestamptz` | YES | `now()` | Дата и время последнего обновления статуса записи |
| **processed_at** | `timestamptz` | YES | `NULL` | Фактическая дата и время завершения обработки экспорта |

### 2. Индексы и ограничения (Indexes & Constraints)

* **`bi_exports_pkey`** (`PRIMARY KEY, btree (id)`) — гарантирует уникальность строк и быстрый доступ по идентификатору записи.
* **`uniq_by_exports_run`** (`UNIQUE, btree (run_id, user_id, operator, type_method)`) — уникальный составной индекс. Предотвращает повторные дублирующие запуски отчетов с одинаковыми параметрами.
* **`idx_bi_exports_status_created`** (`btree (status, created_at)`) — составной индекс для оптимизации очередей. Ускоряет выборку задач по статусам с сортировкой по времени создания.

## Таблица `charging_sessions_fact`

**Описание:** Таблица фактов сессий зарядки электромобилей. Хранит подробные технические, временные и финансовые метрики по каждой совершенной зарядной сессии для последующего анализа и отчетности.

### 1. Структура полей (Columns)

| Столбец | Тип данных | Nullable | По умолчанию | Описание |
| :--- | :--- | :--- | :--- | :--- |
| **id** | `bigint` | NO | `nextval` | Первичный ключ (Primary Key), автоинкремент |
| **user_id** | `integer` | YES | `NULL` | Идентификатор пользователя (клиента) |
| **session_id** | `text` | YES | `NULL` | Уникальный строковый идентификатор сессии зарядки |
| **contract** | `text` | YES | `NULL` | Номер или идентификатор договора / контракта |
| **subscriber_id** | `text` | YES | `NULL` | Идентификатор подписчика в системе |
| **operator** | `text` | YES | `NULL` | Оператор зарядной станции (экосистема / бренд) |
| **charger_name** | `text` | YES | `NULL` | Название или код зарядного столба / терминала |
| **evse_path** | `text` | YES | `NULL` | Путь или адрес конкретной точки EVSE (зарядного порта) |
| **state** | `text` | YES | `NULL` | Текущий статус сессии (например, `COMPLETED`, `CHARGED`) |
| **connector_type** | `text` | YES | `NULL` | Тип разъема / коннектора (например, CCS2, CHAdeMO, Type 2) |
| **evse_type** | `text` | YES | `NULL` | Тип зарядного устройства (например, AC или DC зарядка) |
| **reason** | `text` | YES | `NULL` | Причина завершения или прерывания сессии зарядки |
| **start_ts** | `timestamptz` | YES | `NULL` | Дата и время начала сессии |
| **end_ts** | `timestamptz` | YES | `NULL` | Дата и время окончания сессии |
| **duration_minutes** | `numeric(10,2)` | YES | `NULL` | Общая длительность всей сессии в минутах |
| **energy_kwh** | `numeric(10,3)` | YES | `NULL` | Объем переданной электроэнергии в киловатт-часах (кВт⋅ч) |
| **charge_duration_minutes** | `numeric(10,2)` | YES | `NULL` | Длительность процесса активной зарядки в минутах |
| **post_charge_duration_minutes** | `numeric(10,2)` | YES | `NULL` | Длительность нахождения на станции после окончания зарядки |
| **gross_revenue** | `numeric(10,2)` | YES | `NULL` | Валовая выручка (общая стоимость сессии для клиента) |
| **partner_revenue** | `numeric(10,2)` | YES | `NULL` | Выручка партнера или владельца локации |
| **soc_start** | `integer` | YES | `NULL` | Уровень заряда батареи (SoC) в процентах на старте сессии |
| **current_soc** | `integer` | YES | `NULL` | Текущий или финальный уровень заряда батареи в процентах |
| **soc_delta** | `integer` | YES | `NULL` | Разница уровня заряда батареи за сессию (на сколько % зарядился) |
| **created_at** | `timestamptz` | YES | `now()` | Дата и время создания записи в базе данных |
| **station_id** | `bigint` | YES | `NULL` | Внешний ключ на таблицу зарядной станции |

### 2. Индексы и ограничения (Indexes & Constraints)

* **`charging_sessions_fact_pkey`** (`PRIMARY KEY, btree (id)`) — уникальный ключ строки для быстрой идентификации записи.
* **`uniq_session_id`** (`UNIQUE CONSTRAINT, btree (session_id)`) — ограничение уникальности. Гарантирует отсутствие дубликатов по бизнес-ключу сессии.
* **`charging_sessions_fact_station_id_fkey`** (`FOREIGN KEY`) — связывает запись с таблицей станций (`REFERENCES info_station(id)`).
* **`idx_completed_user_station_start_ts`** (`btree (user_id, station_id, start_ts) WHERE state = ANY (ARRAY['COMPLETED'::text, 'CHARGED'::text])`) — частичный составной индекс. Оптимизирует аналитические выборки по завершенным сессиям конкретных пользователей на конкретных станциях.
* **`idx_cs_completed`** (`btree (user_id, start_ts) WHERE state = ANY (ARRAY['COMPLETED'::text, 'CHARGED'::text])`) — частичный индекс для быстрого построения истории успешных зарядок в профиле пользователя.
* **`idx_cs_user_start_ts`** (`btree (user_id, start_ts)`) — составной индекс для общей фильтрации и сортировки сессий пользователя по времени начала.

## Таблица `run_pipelines`

**Описание:** Таблица логирования и отслеживания запусков конвейеров данных (Pipelines). Хранит информацию о состоянии выполнения процессов обработки, конфигурационных метаданных в формате JSONB и временных метках последних успешных итераций.

### 1. Структура полей (Columns)

| Столбец | Тип данных | Nullable | По умолчанию | Описание |
| :--- | :--- | :--- | :--- | :--- |
| **id** | `bigint` | NO | `nextval` | Первичный ключ (Primary Key), автоинкремент |
| **user_id** | `bigint` | NO | - | Идентификатор пользователя, запустившего или настроившего конвейер |
| **type_method** | `text` | NO | - | Метод, тип обработки или имя конкретного конвейера данных |
| **run_mode** | `text` | NO | - | Режим выполнения процесса (например, по расписанию `scheduled` или вручную `manual`) |
| **operator** | `text` | NO | - | Оператор или подсистема, отвечающая за выполнение конвейера |
| **status** | `pipeline_status` | NO | - | Текущий статус пайплайна (используется пользовательский тип данных `ENUM`) |
| **last_success_at** | `timestamptz` | YES | `NULL` | Дата и время последнего успешного завершения этого конвейера |
| **meta** | `jsonb` | YES | `NULL` | Дополнительные динамические метаданные и параметры запуска в формате JSON |
| **created_at** | `timestamptz` | YES | `now()` | Дата и время инициализации (создания) записи о запуске |
| **run_id** | `text` | YES | `NULL` | Строковый идентификатор конкретного прогона (инстанса) пайплайна |

### 2. Индексы и ограничения (Indexes & Constraints)

* **`run_pipelines_pkey`** (`PRIMARY KEY, btree (id)`) — уникальный ключ для однозначной идентификации конкретного запуска конвейера.
* **`idx_pipeline_lookup`** (`btree (user_id, operator, type_method, run_mode, status, created_at DESC)`) — сложный составной индекс. Оптимизирован для быстрого поиска и фильтрации истории запусков по пользователю, оператору и статусу с сортировкой от самых свежих записей к старым.
